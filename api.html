API Reference¶

The FTK API is built around the scientific Python ecosystem and makes extensive use of ND-arrays. The type hints (ArrayR, ArrayC, ArrayRC) used throughout the API denote placeholders for any array object compliant with the Python array API standard: their goal is to guide the reader when reading the docstrings, and not to perform runtime type-checking.

The API is tested against the following array backends, unless noted otherwise:

  • NumPy

  • CuPy

  • JAX (CPU + GPU)

  • PyTorch (CPU + GPU)

Array Types¶

fourier_toolkit.typing.ArrayC¶

Array-API-compatible array of dtype complex[64,128].

fourier_toolkit.typing.ArrayR¶

Array-API-compatible array of dtype float[32,64].

fourier_toolkit.typing.ArrayRC¶

Array-API-compatible array of dtype (float[32,64], complex[64,128]).

Computing Fourier Sums¶

Note

(nu2nu(), nu2u(), u2nu()) rely on:

  • CPU: FINUFFT

  • GPU: cuFINUFFT

The latter is not installed by default. You can install it if needed via

pip install cufinufft                        # cuda12 pre-packaged [20260711]
pip install --no-binary cufinufft cufinufft  # cudaXX

It may be necessary to modify LD_LIBRARY_PATH afterwards for libcufinufft.so to be importable.

fourier_toolkit.u2u(x_spec, v_spec, w, isign)[source]¶

Multi-dimensional Uniform-to-Uniform Fourier Transform. (\(\tuu\))

Computes the Fourier sum

\[z_{n} = \sum_{m} w_{m} \ee^{ \pm \cj 2\pi \innerProduct{\bbx_{m}}{\bbv_{n}} },\]

where \((\bbx_{m}, \bbv_{n})\) lie on the regular lattice

\[\begin{split}\bbx_{\bbm} &= \bbx_{0} + \Delta_{\bbx} \odot \bbm, \qquad [\bbm]_{d} \in \discreteRange{0}{M_{d}-1}, \\ \bbv_{\bbn} &= \bbv_{0} + \Delta_{\bbv} \odot \bbn, \qquad [\bbn]_{d} \in \discreteRange{0}{N_{d}-1},\end{split}\]

with \(M = \prod_{d} M_{d}\) and \(N = \prod_{d} N_{d}\).

Parameters:

  • x_spec (UniformSpec) – \(\bbx_{m}\) lattice.

  • v_spec (UniformSpec) – \(\bbv_{n}\) lattice.

  • w (ArrayC) – (…, M1,…,MD) weights \(w_{m} \in \bC\).

  • isign (+1, -1) – Exponent sign.

Returns:

z – (…, N1,…,ND) weights \(z_{n} \in \bC\).

Return type:

ArrayC

Notes

  • \(\tuu\) transforms for arbitrary (x_spec,v_spec) can be implemented via the CZT algorithm (using 2 FFTs), but a single FFT can be used in some cases. This implementation chooses the (FFT, CZT) per axis to maximize efficiency.

  • Backend-specific notes:

    • [JAX] supports the following program transforms:

      • jit()

      • vmap()

      • jvp()

      • vjp()

    • [PyTorch] supports the following program transforms:

      • compile(), but it has limited support for complex-valued operators: do not expect huge performance gains.

      • vmap(), but it is currently broken when any transform axis uses the FFT algorithm instead of the CZT algorithm.

      • jvp()

fourier_toolkit.nu2nu(x, v, w, isign, eps=1e-06, finufft_kwargs=())[source]¶

Multi-dimensional NonUniform-to-NonUniform Fourier Transform. (\(\tnunu\))

Computes the Fourier sum

\[z_{n} = \sum_{m} w_{m} \ee^{ \pm \cj 2\pi \innerProduct{\bbx_{m}}{\bbv_{n}} },\]

where \((\bbx_{m}, \bbv_{n}) \in \bR^{D}\).

Parameters:

  • x (ArrayR) – (M, D) knots \(\bbx_{m} \in \bR^{D}\).

  • v (ArrayR) – (N, D) knots \(\bbv_{n} \in \bR^{D}\).

  • w (ArrayC) – (…, M) weights \(w_{m} \in \bC\).

  • isign (+1, -1) – Exponent sign.

  • eps (float) – Target relative error \(\epsilon \in ]0, 1[\). (See Notes.)

  • finufft_kwargs (tuple[tuple[str,int], ...]) – Immutable sequence of (key,value) options for finufft.Plan. Uses FINUFFT’s default option settings if omitted. (For advanced users only.)

Returns:

z – (…, N) weights \(z_{n} \in \bC\).

Return type:

ArrayC

Notes

  • The \(\tnunu\) transform is an approximate transform such that the computed output \(\bbz \in \bC^{N}\) satisfies

    \[\norm{\bbz - \bbz^{GT}}{2} \lesssim \epsilon \norm{\bbz^{GT}}{2}.\]

  • (x,v,w) must share the same (backend,device).

  • The relative error \(\epsilon\) is limited by the precision of (x,v,w):

    • any(x,v,w).dtype = float32 \(\rightarrow \epsilon_{\min}\) = 1e-06

    • all(x,v,w).dtype = float64 \(\rightarrow \epsilon_{\min}\) = 1e-14

  • Backend-specific notes:

    • [JAX] supports the following program transforms:

      • jit()

      • vmap(), but only over (w,) for efficiency reasons.

      • jvp(), but (x, v) are currently not differentiable.

      • vjp(), but (x, v) are currently not differentiable.

    • [PyTorch] currently not supported.

\[\bbv_{\bbn} = \bbv_{0} + \Delta_{\bbv} \odot \bbn, \qquad [\bbn]_{d} \in \discreteRange{0}{N_{d}-1},\]

      • jvp(), but (x,) is currently not differentiable.

      • vjp(), but (x,) is currently not differentiable.

    • [PyTorch] currently not supported.
